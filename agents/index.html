Agents, Tools & Context

Rust sits underneath the agent more often than it is the agent. The Model Context Protocol's official SDK is written in RustSource 1: modelcontextprotocol/rust-sdk, and the isolation layer that hosted agent sandboxes run on is Rust whether or not the product wrapped around it is.

The layers above that line are young: agent frameworks, memory, evaluation and guardrails are mostly work of the last two years, and the cards below carry the dates.

Speaking MCP and ACP. Both protocols publish their official Rust SDK out of the protocol's own organization, which makes Rust a reference implementation language here rather than a port target.

Featured: rmcp [crate · repo · docs]

The official Model Context Protocol SDK, from the protocol's own organization, and the most-depended-on AI crate in the language — ahead of every third-party Rust MCP SDK combined. It tracks the current spec revision with OAuth, streamable HTTP, elicitation, sampling, roots and long-running tasks, and is at a stable 3.x with a published migration guide. Featured: wasmtime [crate · repo · docs]

The default way to run untrusted code in your own process. WebAssembly gives you a memory-safe boundary with an explicit capability list instead of a syscall surface, which is the property you want when the code was written by a model. It is what Extism wraps to make sandboxing one tool ergonomic, and part of the reason Rust is the isolation layer the rest of the 2026 agent stack is built on — even where the product around it is Go or TypeScript.
