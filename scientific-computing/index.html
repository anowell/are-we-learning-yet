Featured: ndarray [crate · repo · docs]

The de-facto n-dimensional array, NumPy's closest analogue, and what most Rust machine learning code is written against — linfa, smartcore, ndarray-stats, ndarray-linalg and rust-numpy all assume it. Rust has no blessed array type and the Rust project has said out loud that it will not pick one, so the honest framing is: ndarray for machine learning, nalgebra for statically-sized geometry, faer for decomposition speed, and they do not interoperate without conversion crates. Know the maintenance position before you build on it: roughly 21 commits in 2026 under a single active maintainer, no 1.0 roadmap, and 0.17.0 was yanked two days after release for a use-after-free reachable without unsafe.

An n-dimensional array for general elements and for numerics. Lightweight array views and slicing; views support chunking and splitting.

Featured: faer [crate · repo · docs]

The fastest Rust option for dense and sparse decompositions, and the one that is credible against OpenBLAS and MKL rather than merely present. It brings its own SIMD abstraction (pulp) and GEMM kernels, and faer-ext converts to and from ndarray and nalgebra so it can be the compute layer under code written against either. Two things to know: its primary host is now Codeberg, with GitHub as a live mirror; and it has no GPU story at all — nothing in the tree, the changelog or the paper.

Python interop comprehensive

Crossing the Rust/Python boundary, and the zero-copy formats for moving tensors and tables across it. Note the asymmetry: shipping a Rust library to Python is a well-trodden path, and going the other way is not.

Featured: numpy [crate · repo · docs]

PyO3 bindings to the NumPy C API, published on crates.io as numpy. It is the crate that makes the Rust-for-Python story work for numerical code specifically: an ArrayView over a NumPy buffer with no copy in either direction, so a Rust function can be the fast path inside an otherwise NumPy workflow without anyone paying for serialization. For tensors rather than arrays, dlpark does the same job over DLPack for PyTorch and JAX.

PyO3-based Rust bindings of the NumPy C-API

Featured: maturin [crate · repo · docs]

Builds and publishes a Python wheel from a Rust crate, including the manylinux and cross-compile parts that make that miserable by hand. Paired with pyo3 it is the whole distribution story for Rust in machine learning: pip install is how tokenizers, safetensors, polars, ruff, uv and pydantic-core actually reach people. If you write a Rust library that a data scientist should use, this is how they get it.

Build and publish crates with pyo3, cffi and uniffi bindings as well as rust binaries as python packages
