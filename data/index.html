Data & Dataframes

Arrow and Parquet are Apache specifications rather than Rust projects — the format publishes a feature matrix across its official implementations, and Rust is one column of itSource 1: arrow.apache.org. Around that column sit the query engines, columnar formats and streaming systems that are Rust top to bottom.

Several of these are Rust implementations whose documented API is the Python one, and several others are servers you deploy rather than crates you depend on. Entries are tagged with which.

Dataframes & query engines comprehensive

Dataframes and the query engines under them. Production-grade and Rust-native, though several are Rust cores with Python-first APIs — check that the Rust API is first-class before you build on it.

Featured: polars [crate · repo · docs]

The dataframe engine, with a funded company behind it and a lazy query optimizer that is genuinely good. It is filed here as a Rust core with a Python API, and that is not a slight — it is what the project's own artifacts say. Python Polars is 1.44 with a written versioning policy and a 2.0 upgrade guide; the Rust crate is 0.55, has no stability guarantee documented anywhere, and the 65 KB upgrade guide contains the words "rust", "crate" and "cargo" exactly zero times. You can absolutely build on it from Rust — plenty do — but expect every minor bump to break you and expect the docs to be written for someone else. If you want a Rust-first engine with a policy attached, that is DataFusion.

Lakehouse & columnar formats comprehensive

Columnar formats and the table layers above them. Arrow is the interchange format that lets everything else on this page talk to everything else, and its Rust implementation is one the Apache project maintains itself.

Featured: arrow [crate · repo · docs]

Apache Arrow in Rust, on a stable semver train in the fifties — and the interchange format that lets everything else on this hub talk to everything else. Polars, DataFusion, Lance, Vortex, delta-rs, iceberg-rust and the Python bindings all speak it, which means a column you produce in one can be read by another without a copy. parquet from the same repository is the on-disk half. If you are moving tabular data across a boundary in Rust, the answer is almost always Arrow.
