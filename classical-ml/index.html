Featured: rv [crate · repo · docs]

Random variables done properly: distributions with conjugate priors and Bayesian updating, which is what separates it from statrs and makes it the base of most Bayesian work in Rust. It is the anchor of a shelf you assemble rather than adopt — pair it with changepoint for online changepoints, ganesh for MCMC, friedrich or egobox-gp for Gaussian processes, adskalman for filtering. What does not exist anywhere in Rust is a probabilistic programming language you would build a project on: every attempt is a solo project under fifty stars.

Bayesian & probabilistic modeling partial

Bayesian and probabilistic modeling. This is a shelf of pieces — priors, samplers, filters, processes, changepoints — that you assemble yourself, rather than a framework you adopt.

Featured: rv [crate · repo · docs]

Random variables done properly: distributions with conjugate priors and Bayesian updating, which is what separates it from statrs and makes it the base of most Bayesian work in Rust. It is the anchor of a shelf you assemble rather than adopt — pair it with changepoint for online changepoints, ganesh for MCMC, friedrich or egobox-gp for Gaussian processes, adskalman for filtering. What does not exist anywhere in Rust is a probabilistic programming language you would build a project on: every attempt is a solo project under fifty stars.

Optimization comprehensive

Linear and mixed-integer programming, convex conic solvers, and derivative-free and gradient-based optimizers. Rust is load-bearing outside Rust here: the standard Python convex-optimization package made a Rust solver its default.Source 1: CVXPY

  1. CVXPY, 2023-09-24 — CVXPY's maintainers, on their own default solver

Featured: good_lp [crate · repo · docs]

An ergonomic linear- and mixed-integer-programming API that dispatches to whichever solver you have: CBC, HiGHS, SCIP, Clarabel or the pure-Rust minilp. You write the model once in Rust expressions and change the backend with a Cargo feature, which is the thing that was missing when every solver had its own bindings and its own matrix layout. If you want the algebraic modeling layer above it — JuMP or Pyomo shaped — that arrived in 2026 as oximo.

Mixed Integer Linear Programming for Rust, with an user-friendly API. This crate allows modeling LP problems, and lets you solve them with various solvers.

Featured: clarabel [crate · repo · docs]

A pure-Rust interior-point solver for convex conic programs, from Oxford Control. It is the piece that makes "Rust can do convex optimization" true without shelling out to a C++ solver, and it is one of the backends good_lp can dispatch to. Together with good_lp, HiGHS and argmin this is the strongest ML-adjacent corner of the Rust numerical stack, and it is the one this site marked red for a decade.
