Featured: ort [crate · repo · docs]

The default answer to "I trained something in Python, how do I run it from Rust?" — a safe wrapper over Microsoft's ONNX Runtime with every execution provider (CUDA, TensorRT, CoreML, DirectML, ROCm, WebGPU, QNN, CANN, RKNPU and more) reachable from Rust. That is the widest accelerator reach available from this language by a wide margin, and it covers scikit-learn and XGBoost models exported through sklearn2onnx as well as neural networks. It is bindings, not a Rust implementation, so you ship a native library alongside your binary; if that is unacceptable, tract and rten are pure Rust at the cost of narrower operator and hardware coverage. Note that 2.0 has been in release candidates since 2024 with no stable version on crates.io at all, so pin an exact one — ort = "=2.0.0-rc.13".

Featured: rten [crate · repo · docs]

A pure-Rust ONNX runtime with no C++ dependency at all: AVX-512, NEON and WASM-SIMD kernels, CPU only. It is the honest answer to "I want ONNX without linking ONNX Runtime", it compiles to WebAssembly, and it is what ocrs runs on — so it has a real end-to-end workload behind it rather than only benchmarks. The trade is explicit: no GPU, and narrower operator coverage than ort, so check your model first. Its rten-examples crate is the most complete worked corpus of loading an ONNX model and doing the pre- and post-processing in Rust.

Featured: safetensors [crate · repo · docs]

The de-facto model weight format, and Rust is its reference implementation. Its contribution is structural rather than performance: the format is a JSON header plus raw tensor bytes with no code path, which is what removed the pickle deserialization attack surface that the entire Python model-scanning industry exists to inspect. Loading is zero-copy and memory-mappable, and every Rust framework here reads it. Repository moved from huggingface/safetensors.

Provides functions to read and write safetensors which aim to be safer than their PyTorch counterpart. The format is 8 bytes which is an unsized int, being the size of a JSON header, the JSON header refers the dtype the shape and data_offsets which are the offsets for the values in the rest of the file.
