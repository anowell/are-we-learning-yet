Retrieval, Embeddings & Search

Search infrastructure is a corner where Rust is the implementation language rather than a binding: the vector databases, the full-text engine underneath hybrid search and the local embedding servers on these shelves are Rust programs, and they publish Rust clients alongside the Python ones most of their users reach for.

Assembling them into a pipeline is the part you still write yourself.

Vector databases & ANN comprehensive

Vector databases and the ANN index crates underneath them. Several of the best-known vector databases are themselves written in Rust and publish first-party Rust clients.

A search engine you can point at a dataset and get relevance from in an afternoon — typo tolerance, faceting, and since 2024 hybrid search with embedders built in, so the keyword and vector halves are one query rather than two systems you reconcile. Featured: qdrant/qdrant [repo]

The dedicated vector database of this shelf, and the one to reach for when the index is the workload rather than a feature of something else. It is one of the few projects here that is Rust all the way down and still keeps a first-class Rust client, which is unusual for a database whose users are mostly writing Python. It is a server you deploy. If you would rather link the index into your own process, LanceDB is the embedded answer; for vectors beside data you already have, sqlite-vec or pgvector.

Featured: fastembed [crate · repo · docs]

The default answer to "how do I embed text from Rust". It bundles a model zoo, batching and rerankers over ONNX Runtime, so you get an embedding without assembling a tokenizer, a runtime and a pooling strategy yourself. It is ort underneath, which means a native library alongside your binary; if you want that in a server instead, Hugging Face's text-embeddings-inference is the Rust one.

Library for generating vector embeddings, reranking locally.

RAG pipelines partial

Chunking, ingesting and keeping a corpus in sync with an index. The chunking primitives are solid; the pipeline frameworks above them are not, so most Rust RAG is assembled by hand out of the shelves either side of this one.

Featured: text-splitter [crate · repo · docs]

Semantic chunking to a token budget, and the one piece of the RAG pipeline where Rust has a best-in-class answer rather than a catch-up one. It splits on the largest semantic unit that fits — section, paragraph, sentence, word — and takes the length function from tiktoken-rs or tokenizers, so the budget is the model's, not an approximation. Most Rust RAG is assembled by hand out of the shelves either side of this one; this is the part you do not have to write.

Split text into semantic chunks, up to a desired chunk size. Supports calculating length by characters and tokens, and is callable from Rust and Python.
