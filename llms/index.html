LLMs & Foundation Models

Rust is a reasonable place to run an open-weights model, and increasingly the language the thing running it is written in: NVIDIA's Dynamo and Cloudflare's Infire are Rust-cored, and the constrained-decoding engine several Python and C++ servers embed is a Rust crate. That is not a recommendation to do your AI work in Rust — the highest-scoring reply in the standing thread on why Rust is uncommon in AI says the oppositeSource 1: users.rust-lang.org.

Calling a model you did not host works for every major provider; most of those crates are community work rather than published by the vendor whose API they wrap.

To build an application on top of a model, see Agents, Tools & Context.

Featured: llama-cpp-2 [crate · repo · docs]

The maintained llama.cpp binding, and the most-used LLM crate in Rust by a wide margin. It buys you every GGUF quantization and every backend llama.cpp supports, at the cost of a C++ build in your pipeline; it is the shortest path from zero to a running local model. Beware llama_cpp (edgenai), an older deprecated crate with a confusingly similar name that people still find first, and llama-cpp-4, a fork. If you want the same job done without linking C++, mistral.rs is the pure-Rust path.

Featured: mistralrs [crate · repo · docs]

The pure-Rust LLM and vision-language engine: built on candle, with PagedAttention, prefix caching, speculative decoding, in-situ quantization and GGUF/GPTQ/AWQ/HQQ/FP8 weights, behind an OpenAI- and Anthropic-compatible server. Two caveats: its crates.io releases trail its GitHub tags by months, so cargo add mistralrs gets older code than the repo; and its image generation is Flux and only Flux, so it is not an answer to "generate an image from Rust".

Featured: llguidance [crate · repo · docs]

The clearest case anywhere of Rust being the substrate the Python AI stack runs on. llguidance computes a token mask against a JSON Schema, regex or Lark grammar in roughly 50 microseconds on a 128k-token vocabulary, and it is the constrained-decoding engine inside vLLM, SGLang, llama.cpp, onnxruntime-genai, TensorRT-LLM, mistral.rs and Chromium. If you need a model to emit something a parser will accept, this is the engine underneath most of the ways you could do it.
